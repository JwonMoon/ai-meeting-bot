파트장님, 말씀 주셨던 AI 회의록 봇, 1차로 동작하는 수준까지 구현되어 진행 상황 공유드립니다.

[어디까지 되나 (현재 상태)]
녹음 파일 하나를 올리면 ① 음성 인식 → ② 회의록 초안 → ③ 담당자 검토·승인 → ④ Confluence 페이지 등록 → Jira 티켓 생성 → Teams 알림까지 한 번에 이어지는 흐름을 사내 GPU 장비(Thor)에서 끝까지 확인했습니다. 시험 음원 기준으로 업로드부터 Confluence 페이지가 생기는 것까지 동작합니다. 처리는 전부 사내 장비 안에서 하고 외부 AI 서비스는 쓰지 않아서, 녹음과 회의 내용이 밖으로 나가지 않습니다.

[어떻게 쓰나 (웹 화면)]
실행은 웹 화면으로 제어하도록 만들었습니다. 별도 프로그램 설치 없이 브라우저(Edge, Chrome)에서 사내 주소를 열면 나오는 화면이고, 파일 올리기와 승인 버튼 정도라 사용법 교육이 거의 필요 없습니다. 화면은 두 장입니다(캡처 참고, 시험 데이터입니다).
- 첫 화면: 녹음 파일을 올리고 회의 이름을 적는 칸, 그리고 지금까지 올린 회의 목록과 각 상태(음성 인식 중 / 검토 대기 / 게시 완료 / 실패)가 보입니다. 올리면 음성 인식과 초안 작성이 자동으로 시작됩니다.
- 검토 화면: 초안의 제목·요약·안건·결정 사항·액션아이템이 수정 가능한 칸으로 나옵니다. 담당자가 틀린 곳을 고치고, Confluence 상위 페이지와 Jira 프로젝트를 고른 뒤 "승인하고 게시"를 누르면 그때 비로소 등록됩니다. 승인 전에는 어디에도 보내지 않습니다. 중간에 실패하면 어느 단계에서 왜 실패했는지 보여 주고 그 단계부터 다시 할 수 있습니다.
- 추후에는 Teams에서 바로 파일을 올리고 승인까지 하는 방식도 고려하고 있습니다. 지금은 웹 화면이 먼저입니다.

[실제 녹음으로 해 본 결과 (오늘)]
오늘 위원님과의 기술 미팅 녹음을 올려 봤는데, 질적인 이슈가 두 가지 있었습니다.
- 음성 인식이 앞부분 일부만 되고 뒤가 잘렸습니다. 조용한 회의실 녹음을 "말 없는 구간"으로 잘못 판정해 건너뛴 것이 원인으로 추정되어, 판정 기준을 녹음 소리 크기에 맞춰 자동 조정하도록 수정했고 재검증 중입니다.
- 회의록 초안의 품질이 아직 부족합니다. 위 문제로 입력 자체가 일부였던 영향이 크지만, 그와 별개로 더 큰 언어 모델 적용, 긴 회의를 나눠 요약하는 방식, 회의 정보(참석자·안건) 입력을 순서대로 시도해서 차츰 개선할 계획입니다.

[남은 과제]
- 실제 회의 녹음으로 재검증 (녹음 방법 포함: 마이크 위치 등)
- 회의록 품질 개선 (위 순서대로)
- 운영 준비: 봇 전용 계정 토큰, 봇 전용 음성 인식 환경 분리, 서버 자동 시작

흐름은 완성됐고 지금부터는 품질을 올리는 단계라고 보시면 됩니다. 시범 적용할 회의나 우선순위에 대해 의견 주시면 반영하겠습니다. 감사합니다.
